Besides the grommunio Appliance and a manual installation, grommunio runs in
containers. The [gromox-container](https://github.com/grommunio/gromox-container)
project provides the images and a Docker Compose deployment for a single host.
For Kubernetes, the same images are deployed with a Helm chart, see
[Kubernetes](/admin/kubernetes/).

The images are based on openSUSE Leap 16.0 and install the grommunio packages
from the official repositories. Inside each container, supervisord manages the
services. The databases run in separate MariaDB 11 containers.

:::caution[Default passwords]
`var.env` and `docker-compose.yml` ship with default passwords that are publicly
known. Change all of them before the deployment is reachable from the network.
gromox-core logs a warning on every start while a default value is still in use.
:::

## Images and containers

| Container | Image | Purpose |
| --- | --- | --- |
| `gromox-core` | `gromox-core` | Groupware services: nginx, Postfix, the Gromox daemons (http, imap, pop3, delivery, delivery-queue, zcore, midb, event), Admin API, antispam (rspamd), grommunio Chat, PHP-FPM, Redis, saslauthd, cron |
| `gromox-archive` | `gromox-archive` | grommunio Archive: archive daemon, archive SMTP receiver, Sphinx search and indexers, nginx, PHP-FPM |
| `gromox-office` | `gromox-office` | grommunio Files and grommunio Office: document server, converter, RabbitMQ, nginx, PHP-FPM, Redis, cron |
| `gromox-db` | `mariadb:11` | Core database `grommunio` |
| `chat-db`, `files-db`, `office-db`, `archive-db` | `mariadb:11` | Databases of Chat, Files, Office and Archive |

All containers share the Compose network `grommunio`. Only `gromox-core`
publishes ports on the host; its nginx proxies `/files`, `/office` and
`/archive` to the other containers.

The service containers need no `privileged: true`, no `SYS_ADMIN` capability
and no special runtime. All listeners that are reachable from outside a container
use ports above 1024; Compose maps the standard ports on the host to them (see
[Ports](#ports)).

## Requirements

- Docker Engine with Docker Compose v2.24 or newer (`docker compose version`)
- At least 4 GB RAM for gromox-core, 8 GB with grommunio Office
- A DNS name (`FQDN`) that resolves to the host. For Let's Encrypt
  certificates, port 80 must be reachable from the internet.
- The host ports listed under [Ports](#ports) must be free.

SELinux hosts (openSUSE Leap 16, Fedora, RHEL) need no extra steps: the only
bind mount, `./gromox_letsencrypt`, is declared with the `z` label.

## Quick start

<Steps>

1. Get the project:

   ```sh
   git clone https://github.com/grommunio/gromox-container.git
   cd gromox-container
   ```

2. Create `var.local.env` with your own values. `var.env` holds the defaults
   and is tracked in git; do not edit it. `var.local.env` is ignored by git,
   read after `var.env` and overrides it:

   ```sh
   cat > var.local.env <<'ENV'
   FQDN=mail.example.com
   DOMAIN=example.com
   ADMIN_PASS=ChangeMe
   CHAT_ADMIN_PASS=ChangeMe
   FILES_ADMIN_PASS=ChangeMe
   SSL_INSTALL_TYPE=2
   ENV
   ```

3. Set the database passwords. In `docker-compose.yml`, change
   `MARIADB_PASSWORD` and `MARIADB_ROOT_PASSWORD` of the five MariaDB services,
   and set the matching values in `var.local.env`:

   | MariaDB service | Variables in `var.local.env` |
   | --- | --- |
   | `gromox-db` | `MYSQL_PASS`, `MYSQL_ROOT_PASS` (root password, only used with `CLEAR_DBS=true`) |
   | `chat-db` | `CHAT_MYSQL_PASS` |
   | `files-db` | `FILES_MYSQL_PASS` |
   | `office-db` | `OFFICE_MYSQL_PASS` |
   | `archive-db` | `ARCHIVE_MYSQL_PASS` |

   MariaDB applies these passwords only when it initializes an empty data
   volume. Set them before the first start.

4. Start the stack:

   ```sh
   docker compose up -d
   ```

   The first start takes several minutes while the containers initialize the
   databases, create the certificate and configure the services. Follow the
   progress with `docker compose logs -f gromox-core`. `docker compose ps`
   reports each container as `healthy` once all of its services run.

</Steps>

:::note[Value syntax]
Docker Compose parses `var.env` and `var.local.env`. Write a literal `$` as
`$$` or put the value in single quotes, and do not use ` #` (space followed by
`#`) inside a value: it starts a comment.
:::

### Accessing the services

| Service | URL |
| --- | --- |
| grommunio Web | `https://<FQDN>/` |
| Admin UI | `https://<FQDN>:8443/` |
| Exchange ActiveSync | `https://<FQDN>/Microsoft-Server-ActiveSync` |
| CalDAV / CardDAV | `https://<FQDN>/dav/` |
| grommunio Chat (if enabled) | `https://<FQDN>/chat/` |
| grommunio Files (if enabled) | `https://<FQDN>/files/` |
| grommunio Archive (if enabled) | `https://<FQDN>/archive/` |

Sign in to the Admin UI as `admin` with the password from `ADMIN_PASS`, then
create a domain and users. Users sign in to grommunio Web, IMAP and SMTP with
their e-mail address. grommunio Archive has the built-in accounts
`admin@local` and `auditor@local`.

## Using the prebuilt images

Instead of building the images locally, you can pull signed images from the
grommunio container registry at `container.grommunio.com`:

| Project | Access | Built from |
| --- | --- | --- |
| `community/` | public, no login | grommunio community packages |
| `supported/` | grommunio subscription customers | grommunio supported packages |

Both projects contain `gromox-core`, `gromox-archive` and `gromox-office`. The
tag `2026.11` points to the newest build of that release; see
[Container registry](/admin/container_registry/) for the tag scheme, pull
credentials and air-gapped installations.

<Steps>

1. Verify the signature of each image with
   [cosign](https://docs.sigstore.dev/cosign/) and the public key `cosign.pub`
   from the gromox-container repository:

   ```sh
   cosign verify --key cosign.pub container.grommunio.com/community/gromox-core:2026.11
   cosign verify --key cosign.pub container.grommunio.com/community/gromox-archive:2026.11
   cosign verify --key cosign.pub container.grommunio.com/community/gromox-office:2026.11
   ```

2. For the `supported/` images, log in with the robot account provided with
   your subscription. Quote the user name, it contains a `$`:

   ```sh
   docker login container.grommunio.com -u 'robot$supported+<customer>'
   ```

3. In `docker-compose.yml`, replace the `build:` block of `gromox-core`,
   `gromox-archive` and `gromox-office` with an `image:` line:

   ```yaml
   services:
     gromox-core:
       image: container.grommunio.com/community/gromox-core:2026.11
       container_name: gromox-core
       # ... rest unchanged
     gromox-archive:
       image: container.grommunio.com/community/gromox-archive:2026.11
       # ...
     gromox-office:
       image: container.grommunio.com/community/gromox-office:2026.11
       # ...
   ```

   For subscription images use `container.grommunio.com/supported/...`.

4. Pull the images and start the stack:

   ```sh
   docker compose pull
   docker compose up -d
   ```

</Steps>

For reproducible deployments, pin a build tag (`2026.11-<YYYYMMDDhhmm>`) or an
image digest instead of the moving release tag.

## Configuration

All settings are environment variables. Compose passes them to the
`gromox-core`, `gromox-archive` and `gromox-office` containers from these files,
in this order (later files override earlier ones):

1. `var.env`: defaults, tracked in git
2. `variables_data/var.env`: optional, the location used by earlier versions
3. `var.local.env`: optional, your settings, ignored by git

All three service containers read the same files, so feature flags and host
names always match.

### Identity and administration

| Variable | Description | Default in `var.env` |
| --- | --- | --- |
| `FQDN` | Fully qualified host name of the server (required) | placeholder, set your own |
| `DOMAIN` | Mail domain (required) | placeholder, set your own |
| `ADMIN_PASS` | Password of the grommunio `admin` user, also used for the rspamd web interface (required) | `admin` |
| `TIMEZONE` | Time zone of the containers | `Europe/Vienna` |
| `RELAYHOST` | Outbound SMTP relay as `[host]:port`; empty means direct delivery | empty |
| `X500` | X.500 organization identifier; generated on the first start if empty | |

gromox-core does not start if `FQDN`, `DOMAIN`, `ADMIN_PASS` or `MYSQL_PASS`
is empty.

### Databases

| Variables | Description | Default in `var.env` |
| --- | --- | --- |
| `MYSQL_HOST`, `MYSQL_USER`, `MYSQL_PASS`, `MYSQL_DB` | Core database | `gromox-db`, `grommunio`, default password, `grommunio` |
| `MYSQL_ROOT_PASS` | Root password of `gromox-db`, only needed with `CLEAR_DBS=true` | default password |
| `CHAT_MYSQL_HOST`, `CHAT_MYSQL_USER`, `CHAT_MYSQL_PASS`, `CHAT_MYSQL_DB` | grommunio Chat database | `chat-db`, `grochat`, `grommunio`, `grochat` |
| `FILES_MYSQL_HOST`, `FILES_MYSQL_USER`, `FILES_MYSQL_PASS`, `FILES_MYSQL_DB` | grommunio Files database | `files-db`, `grofiles`, `grommunio`, `grofiles` |
| `OFFICE_MYSQL_HOST`, `OFFICE_MYSQL_USER`, `OFFICE_MYSQL_PASS`, `OFFICE_MYSQL_DB` | grommunio Office database | `office-db`, `groffice`, `grommunio`, `groffice` |
| `ARCHIVE_MYSQL_HOST`, `ARCHIVE_MYSQL_USER`, `ARCHIVE_MYSQL_PASS`, `ARCHIVE_MYSQL_DB` | grommunio Archive database | `archive-db`, `groarchive`, `grommunio`, `groarchive` |

The values must match the `MARIADB_*` settings of the corresponding service in
`docker-compose.yml`.

### Optional components

| Component | Switch (default in `var.env`) | Further variables |
| --- | --- | --- |
| grommunio Chat | `ENABLE_CHAT=true` | `CHAT_ADMIN_PASS` (password of the Chat system admin `admin`), `CHAT_CONFIG` (default `/etc/grommunio-chat/config.json`) |
| grommunio Files | `ENABLE_FILES=true` | `FILES_ADMIN_PASS` (Files admin `admin`), `FILES_HOST` (default `gromox-office`), `TRUSTED_PROXIES` (networks Files trusts as reverse proxies, default the Compose network) |
| grommunio Office | `ENABLE_OFFICE=true` | `OFFICE_HOST` (default `gromox-office`) |
| grommunio Archive | `ENABLE_ARCHIVE=true` | see below |
| Keycloak SSO | `ENABLE_KEYCLOAK=false` | `KEYCLOAK_URL`, `KEYCLOAK_REALM`, `KEYCLOAK_CLIENT_ID`, `KEYCLOAK_CLIENT_SECRET` |

With `ENABLE_CHAT=true`, `CHAT_MYSQL_PASS` and `CHAT_ADMIN_PASS` must be set;
with `ENABLE_FILES=true`, `FILES_MYSQL_PASS` and `FILES_ADMIN_PASS`; with
`ENABLE_OFFICE=true`, `OFFICE_MYSQL_PASS`. gromox-archive always needs
`ARCHIVE_MYSQL_PASS`.

grommunio Archive:

| Variable | Description | Default |
| --- | --- | --- |
| `ARCHIVE_HOST` | Host name of the archive container | `gromox-archive` |
| `ARCHIVE_ADMIN_PASS` | Password of the built-in account `admin@local` | value of `ADMIN_PASS` |
| `ARCHIVE_AUDIT_PASS` | Password of the built-in account `auditor@local` | value of `ADMIN_PASS` |
| `ARCHIVE_RETENTION_DAYS` | Retention of newly archived mail, in days | `2557` (7 years) |
| `ARCHIVE_INDEXER_DELTA_INTERVAL` | Interval of the Sphinx delta indexer (`600`, `10m`, `1h`) | `10m` |
| `ARCHIVE_INDEXER_MAIN_INTERVAL` | Interval of the housekeeping run (index merge, purge, signing, statistics) | `24h` |
| `ARCHIVE_NEW_KEY` | `true` lets gromox-archive create a new encryption key although the archive database already references mails; those mails become unreadable | `false` |

### TLS certificates

| Variable | Description | Default |
| --- | --- | --- |
| `SSL_INSTALL_TYPE` | `0`: certificate from a built-in CA; `2`: Let's Encrypt; `3`: own certificate | `0` |
| `SSL_BUNDLE`, `SSL_KEY` | Type `3`: paths inside gromox-core of the full-chain certificate and the private key | |
| `SSL_EMAIL` | Contact address for Let's Encrypt | `admin@<DOMAIN>` |
| `MAIL_DOMAINS` | Additional names for the Let's Encrypt certificate, comma-separated | |

**Built-in CA** (`0`): gromox-core creates a local CA and issues a server
certificate valid for 10 years. On a start within 30 days of its expiry, the
certificate is renewed. All containers trust the CA. Install the CA certificate on your clients to avoid
certificate warnings:

```sh
docker cp gromox-core:/etc/grommunio-common/ssl/ca.pem grommunio-ca.pem
```

**Let's Encrypt** (`2`): certbot requests the certificate on the first start;
port 80 must be reachable from the internet. A cron job attempts the renewal
every 12 hours, deploys a renewed certificate and restarts the TLS services.
nginx is stopped only while a renewal actually runs. If certbot fails, an
existing certificate is kept; without one, a certificate from the built-in CA
is used and certbot is retried on later starts, at most once per hour.

**Own certificate** (`3`): mount the certificate and key into gromox-core,
for example in a `docker-compose.override.yml`, and set the paths in
`var.local.env`:

```yaml
services:
  gromox-core:
    volumes:
      - ./certs:/etc/grommunio-common/ssl/own:ro
```

```ini
SSL_INSTALL_TYPE=3
SSL_BUNDLE=/etc/grommunio-common/ssl/own/fullchain.pem
SSL_KEY=/etc/grommunio-common/ssl/own/privkey.pem
```

gromox-core copies the files into the shared certificate volume on every
start. After replacing the certificate, run
`docker compose restart gromox-core gromox-archive gromox-office`.

### Maintenance

| Variable | Description | Default |
| --- | --- | --- |
| `INDEX_SCHEDULE` | cron schedule of the full-text search index for grommunio Web (`grommunio-index`); empty disables it | `*/15 * * * *` |
| `FORCE_RECONFIG` | `true` re-runs the one-time initialization of gromox-core on the next start: certificate check, admin password set to `ADMIN_PASS`, Chat admin. The database initialization is not repeated. | `false` |
| `CLEAR_DBS` | `true` drops and recreates a populated core database when the database initialization runs (first start with an empty `gromox_config` volume). Requires `MYSQL_ROOT_PASS`. | `false` |
| `CORE_HOST` | Host name of gromox-core as seen from the archive and office containers (mail relay) | `gromox-core` |
| `LOGFILE` | Setup log | `/var/log/grommunio-setup.log` |

:::danger[CLEAR_DBS destroys data]
With `CLEAR_DBS=true` the core database is dropped, including all users,
domains and mailbox metadata. Use it only for a deliberate reinstallation.
:::

## Ports

| Host port | Container port | Protocol | Service |
| --- | --- | --- | --- |
| 25 | 2525 | SMTP | Postfix, inbound mail |
| 80 | 8081 | HTTP | nginx: Let's Encrypt challenges, redirect to HTTPS |
| 443 | 8443 | HTTPS | nginx: grommunio Web, ActiveSync, DAV, Files, Office, Archive |
| 465 | 2465 | SMTPS | Postfix, implicit TLS, authenticated submission |
| 587 | 2587 | Submission | Postfix, STARTTLS, authenticated submission |
| 993 | 2993 | IMAPS | Gromox IMAP over TLS |
| 143 | 2143 | IMAP | Gromox IMAP, STARTTLS |
| 995 | 2995 | POP3S | Gromox POP3 over TLS |
| 110 | 2110 | POP3 | Gromox POP3, STARTTLS |
| 8443 | 9443 | HTTPS | Admin UI |

gromox-archive (8443, archive SMTP on 2693) and gromox-office (8443) are
reachable on the Compose network only.

## Volumes

Everything that is not on a volume is regenerated from the environment on every
start. Containers can therefore be recreated, for an image update or after a
configuration change, without losing data.

| Volume | Mount point | Content |
| --- | --- | --- |
| `gromox` | `/var/lib/gromox` | Mailboxes |
| `gromox_config` | `/etc/gromox` | Gromox configuration, X.500 identifier, initialization markers |
| `cert_data` | `/etc/grommunio-common/ssl` | TLS certificate and key, shared by all containers |
| `postfix_spool` | `/var/spool/postfix` | Mail queue |
| `redis_data` | `/var/lib/redis` | rspamd statistics (Bayes), greylisting, history |
| `grommunio_admin_api` | `/var/lib/grommunio-admin-api` | Admin API data |
| `grommunio_admin_config` | `/etc/grommunio-admin-api` | Admin API configuration (LDAP settings) and JWT signing key |
| `grommunio_admin_license` | `/etc/grommunio-admin-common/license` | Uploaded license |
| `grommunio_antispam` | `/var/lib/grommunio-antispam` | Antispam data |
| `grommunio_dav` | `/var/lib/grommunio-dav` | CalDAV/CardDAV synchronization state |
| `grommunio_web` | `/var/lib/grommunio-web` | grommunio Web sessions and search indexes |
| `grommunio_chat_config` | `/etc/grommunio-chat` | Chat configuration |
| `grommunio_chat_data` | `/var/lib/grommunio-chat` | Chat uploads |
| `files_data` | `/var/lib/grommunio-files` | Files configuration and user data |
| `office_data` | `/var/lib/grommunio-office` | Office document cache and the Files/Office JWT secret |
| `archive_data` | `/var/lib/grommunio-archive` | Archive store, search index and encryption key |
| `opensuse_data`, `gromox_services` | `/data`, `/home/gromox-services` | Legacy volumes |
| `gromox_mysql_data` | MariaDB data directory | Core database |
| `chat_mysql_data`, `files_mysql_data`, `office_mysql_data`, `archive_mysql_data` | MariaDB data directory | Chat, Files, Office and Archive databases |
| `./gromox_letsencrypt` (bind mount) | `/etc/letsencrypt` | Let's Encrypt account, certificates and renewal state |

Compose prefixes the volume names with the project name: the volume `gromox`
is called `grommunio_gromox` on the host.

## Operations

### Service status and logs

```sh
docker compose ps                                # healthy = all services run
docker exec gromox-core supervisorctl status
docker exec gromox-archive supervisorctl status
docker exec gromox-office supervisorctl status

docker exec gromox-core supervisorctl restart postfix

docker compose logs gromox-core                  # entrypoint and configuration
docker exec gromox-core cat /var/log/grommunio-setup.log
docker exec gromox-core cat /var/log/supervisord.log
docker exec gromox-core tail -f /var/log/supervisor-postfix.log
docker exec gromox-core cat /var/log/supervisor-gromox-imap-err.log
```

### Changing the configuration

Edit `var.local.env` and recreate the containers:

```sh
docker compose up -d
```

Settings derived from the environment (host names, feature flags, nginx,
Postfix, Gromox and Files settings) are applied on every start, as are the
passwords of the rspamd web interface (`ADMIN_PASS`) and of the Archive
accounts `admin@local` and `auditor@local`. The passwords of the grommunio
`admin` user and of the Chat and Files admins are set only once. To reset the
`admin` password to `ADMIN_PASS`, set `FORCE_RECONFIG=true`, run
`docker compose up -d`, and remove the setting again.

### Backup

Dump the databases and archive the data volumes:

```sh
mkdir -p backup

for db in gromox-db chat-db files-db office-db archive-db; do
  docker exec $db sh -c 'mariadb-dump --all-databases -uroot -p"$MARIADB_ROOT_PASSWORD"' > backup/$db.sql
done

for v in gromox gromox_config cert_data grommunio_admin_config grommunio_admin_license \
         files_data archive_data grommunio_chat_config grommunio_chat_data redis_data; do
  docker run --rm -v grommunio_$v:/data -v "$(pwd)/backup:/backup" busybox \
    tar czf /backup/$v.tar.gz /data
done

tar czf backup/letsencrypt.tar.gz gromox_letsencrypt/
```

On SELinux hosts, append `:z` to the `/backup` mount. The `archive_data` volume
holds the archive encryption key: without it, archived mail cannot be read. For
consistent backups and single-mailbox restores, see
[Backup and restore](/guides/backup-restore/).

### Updating

With locally built images:

```sh
git pull
docker compose build --pull
docker compose up -d
```

With images from `container.grommunio.com`, change the tag in
`docker-compose.yml` if you move to a new release, then:

```sh
docker compose pull
docker compose up -d
```

Schema upgrades run automatically on start: the Gromox schema through
`gromox-http`, grommunio Files through `occ upgrade`, MariaDB through
`MARIADB_AUTO_UPGRADE`.

:::caution[Updating from earlier container versions]
Earlier versions of the project had you edit the tracked `var.env` and copy it
to `variables_data/var.env`, and kept the archive store and key, the Files data
and the Chat uploads inside the containers instead of on volumes. Before
updating such a deployment, follow "Upgrading from the previous container
layout" in the
[project README](https://github.com/grommunio/gromox-container#upgrading-from-the-previous-container-layout).
:::

### Resetting

```sh
docker compose down -v
docker compose up -d
```

:::danger[All data is lost]
`docker compose down -v` removes the containers and all volumes, including
every mailbox and database.
:::

## Building the images yourself

`docker compose build` builds the images from the grommunio community packages.
`tools/publish-images.sh` builds the three images for a channel and pushes them
to your own registry, signed with your own cosign key:

```sh
cosign generate-key-pair
COSIGN_KEY=cosign.key COSIGN_PASSWORD=... \
  tools/publish-images.sh -r registry.example.com -c community
tools/publish-images.sh -r registry.example.com --no-sign   # push unsigned
tools/publish-images.sh -n -c community                      # build only
```

| Option | Effect |
| --- | --- |
| `-c community\|supported` | Package channel |
| `-r REGISTRY` | Target registry |
| `-t TAG` | Release tag (default: the `appVersion` of the Helm chart) |
| `-b BUILD_ID` | Build suffix of the unique tag `<TAG>-<BUILD_ID>` (default: UTC date and time, `YYYYMMDDhhmm`) |
| `-n` | Build without pushing |
| `--no-sign` | Push without a cosign signature |
| `--no-cache` | Rebuild every layer to pick up updated packages |
| `--latest` | Also tag `latest` |
| `core archive office` | Components to build (default: all three) |

Builds of the `supported` channel need the subscription credentials in zypper
credentials format. They are passed as a BuildKit secret and are not stored in
the image:

```sh
printf 'username=%s\npassword=%s\n' '<subscription user>' '<subscription password>' \
  > supported.credentials
SUPPORTED_CREDENTIALS=$PWD/supported.credentials \
  tools/publish-images.sh -r registry.example.com -c supported
```

## Security

- The service containers run without privileged mode or added capabilities;
  all listeners reachable from outside a container use ports above 1024.
- Images from `container.grommunio.com` are signed with cosign and scanned for
  known vulnerabilities; the registry serves only signed images. See
  [Container registry](/admin/container_registry/).
- Postfix (25, 465, 587) disables SSLv2, SSLv3, TLS 1.0 and TLS 1.1 and excludes
  `aNULL, eNULL, EXP, MD5, RC4, DES, 3DES, DHE, EDH, kDHE, kEDH, ADH`. The
  finite-field DHE key exchange is excluded; ECDHE suites with forward secrecy
  remain available.
- Gromox http, imap and pop3 use `tls_min_proto = tls1.2`. TLS 1.2 remains
  enabled for mail clients that do not support TLS 1.3.
- Postfix trusts (`mynetworks`) only loopback and the Compose network, without
  the network gateways through which Docker forwards connections from the host.
  All other clients must authenticate to relay mail.
- The setup log is readable by root only.

Change all default passwords, restrict access to the Admin UI port 8443, and
use Let's Encrypt or a certificate from your own CA in production.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Container restarts during the first start | `docker compose logs gromox-core`. The entrypoint exits when the database is unreachable or a required variable (`FQDN`, `DOMAIN`, passwords) is missing. `docker compose ps` shows whether the databases are healthy. |
| A service is in state `FATAL` | `docker exec gromox-core cat /var/log/supervisor-<service>-err.log` |
| `/files` or `/archive` returns 502 | gromox-core proxies these paths to the other containers. Check that gromox-office and gromox-archive are healthy and that the `ENABLE_*` flags are set consistently. |
| Chat does not start | Chat runs only with `ENABLE_CHAT=true` and an existing `CHAT_CONFIG`: `docker exec gromox-core supervisorctl status grommunio-chat` |
| gromox-archive refuses to start | The archive database references mails, but the volume holds no encryption key. Restore the key, or set `ARCHIVE_NEW_KEY=true` to start a new archive store. |
| Let's Encrypt certificate missing | Port 80 must be reachable from the internet and `FQDN` must resolve to the host. Until certbot succeeds, the built-in CA certificate is used. |
| A service does not accept connections | `docker exec gromox-core ss -tlnp` lists the listeners inside gromox-core. nginx listens on 8081, 8443, 9443 and, internally, 8080. |

The Admin UI shows fetchmail settings, but fetchmail is not installed in the
image; these settings have no effect.
